# ShoeStore — Магазин обуви
Учебный проект: десктопное приложение для автоматизации учета товаров и заказов.
## Возможности
- Просмотр каталога обуви
- Поиск и фильтрация товаров
- Оформление заказов
## Требования
- Python 3.9+
- PostgreSQL 13+
## Установка и запуск
1. Клонировать репозиторий.
2. Установить зависимости: `pip install -r requirements.txt`.
3. Скопировать `config.py.example` в `config.py` и указать свои параметры подключения.
4. Запустить приложение: `python main.py`.

## Запуск PostgreSQL через Docker Compose

Проект использует PostgreSQL, запущенный в Docker-контейнере. Это позволяет не устанавливать СУБД на компьютер и легко управлять базой данных.

### 1. Предварительные требования и установка Docker
Для работы приложения необходима среда контейнеризации:
1. Скачайте и установите **Docker Desktop** с официального сайта: [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/).
2. При установке на Windows убедитесь, что выбрана опция **"Use WSL 2 instead of Hyper-V"** (Использовать WSL 2).
3. После установки запустите Docker Desktop и дождитесь, пока индикатор в трее не покажет статус **"Running"** (зеленый значок кита).
4. Установите **Python 3.9+** с официального сайта.
5. Убедитесь, что порт, который вы планируете использовать (по умолчанию **5433**), свободен.

### 2. Создание файла .env
Для запуска базы данных необходимо создать локальный файл конфигурации:
1. В корне проекта найдите файл `.env.example`.
2. Создайте его копию и переименуйте в `.env`.
3. Откройте `.env` в текстовом редакторе и замените значение `POSTGRES_PASSWORD` на свой надежный пароль (например, `qw1`).
4. **Важно:** Если порт `5433` уже занят на вашем компьютере, вы можете изменить его на любой свободный порт в строке `POSTGRES_HOST_PORT`.
   *Пример содержимого:*
   ```text
   POSTGRES_DB=shoe_store
   POSTGRES_USER=postgres
   POSTGRES_PASSWORD=qw1
   POSTGRES_HOST_PORT=5433
## Постоянное хранение и сети

### Назначение тома `db_data`

В проекте используется именованный том Docker `db_data`, который подключается к каталогу данных PostgreSQL. Это обеспечивает **сохранность данных** даже при удалении или пересоздании контейнера. Все таблицы, записи и изменения, внесенные в базу данных, хранятся в этом томе и не теряются при перезапуске.

### Резервное копирование и восстановление

Регулярное резервное копирование позволяет защитить данные от случайного удаления или сбоев.

**Создание резервной копии:**

1. Создайте дамп базы внутри контейнера:

   ```bash
   docker compose exec db pg_dump -U postgres -d shoe_store -f /tmp/backup.sql
   ```

2. Скопируйте файл на компьютер:

   ```bash
   docker compose cp db:/tmp/backup.sql ./backups/shoe_store_backup.sql
   ```

**Восстановление из резервной копии:**

1. Скопируйте файл обратно в контейнер:

   ```bash
   docker compose cp ./backups/shoe_store_backup.sql db:/tmp/restore.sql
   ```

2. Выполните восстановление:

   ```bash
   docker compose exec db psql -U postgres -d shoe_store -f /tmp/restore.sql
   ```

### Команды запуска

Для запуска инфраструктуры выполните в корне проекта:

```bash
docker compose up -d
```

Для проверки статуса:

```bash
docker compose ps
```

Для остановки без удаления данных:

```bash
docker compose stop
```

### Сетевые адреса

К одной и той же базе данных можно подключиться двумя способами, в зависимости от того, откуда выполняется подключение:

- **Из контейнера (внутри Docker-сети):** адрес `db:5432`. Его использует сервис `db-check`.
- **С компьютера (Windows):** адрес `localhost:5433`. Его использует приложение ShoeStore.

Внутри Docker-сети контейнеры обращаются друг к другу по именам сервисов (`db`) и используют внутренний порт PostgreSQL — `5432`.

С компьютера используется опубликованный порт `5433`, который перенаправляется на порт `5432` контейнера `db` (настроено в `docker-compose.yml`: `"5433:5432"`).

### Предупреждение

**Не выполняйте команду `docker compose down -v`!**

Флаг `-v` удаляет все именованные тома, объявленные в проекте, включая `db_data`. Это приведет к полной потере всех данных в базе. Если вам нужно остановить контейнеры, используйте `docker compose stop` или `docker compose down` (без `-v`).
